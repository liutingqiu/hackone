# hackone 组织架构

> 一支 AI 协作小队：每个部门一个 bot，各有工作区、职责与留痕义务。
> 目的有两个：**把活拆开并行**，以及**过程可验证**（评委可能核查是否现场创作）。

---

## 一、组织图

```
                    ┌──────────────┐
                    │  统筹 chief  │  主 bot，唯一对外接口
                    └──────┬───────┘
        ┌──────────┬───────┼────────┬──────────┐
        ▼          ▼       ▼        ▼          ▼
   ┌────────┐ ┌────────┐ ┌──────┐ ┌────────┐ ┌────────┐
   │ 调研部 │ │ 开发部 │ │测试部│ │ 运维部 │ │ 设计部 │
   │research│ │  dev   │ │  qa  │ │  ops   │ │design※ │
   └────────┘ └────────┘ └──────┘ └────────┘ └────────┘
```

※ 设计部本期并入开发部，不单设 bot。

## 二、部门与 bot

| 部门 | bot 名 | 工作区 | 职责一句话 |
| --- | --- | --- | --- |
| 统筹 | 柳（主 bot） | `hackone/` | 拆任务、分派、验收、对外 |
| 调研 | 探 | `hackone/` | 市场、竞品、用户访谈、数据 |
| 开发 | 匠 | `hackone/web/` | 引擎、界面、分板功能 |
| 测试 | 证 | `hackone/web/` | 用例、自动化、验收报告 |
| 运维 | 航 | `hackone/` | 构建、部署、域名、回滚 |

每个 bot 的完整职责见 `org/<部门>/ROLE.md`。

## 三、协作协议

### 产物放哪

| 类型 | 位置 | 命名 |
| --- | --- | --- |
| 调研结论 | `docs/` | `<主题>.md` |
| 代码 | `web/src/` | 按模块分目录 |
| 测试用例 | `web/src/**/*.test.ts` | 与被测文件同名 |
| 部署配置 | `.github/workflows/`、`wrangler.toml` | — |
| 留痕 | `journal/YYYY-MM-DD.log` | 见下 |

### 交接方式

不口头交接，只通过「产物 + 一条留痕」。下家从留痕里读到上家做了什么、证据在哪。

### 留痕要求（强制）

任何部门做完一件事，必须执行：

```bash
./tools/journal.sh <部门> "<做了什么>" "<证据>"
```

例：

```
./tools/journal.sh dev "实现分板切分算法" "web/src/lib/split.ts + 6 个单测"
./tools/journal.sh qa "分板用例人工验收通过" "docs/evidence/split-100x100.png"
```

写入 `journal/2026-11-07.log`，格式：

```
[11:23:41] dev      实现分板切分算法            证据: web/src/lib/split.ts + 6 个单测
```

**为什么这么做**：git 提交记录只有代码，没有「谁在什么时候决定做什么」。留痕补的是决策与验证链，评委问"这是现场做的吗"，直接给日志 + 提交时间线。

## 四、留痕的可验证性

| 证据 | 证明什么 |
| --- | --- |
| `journal/*.log` 时间戳 | 工作发生的顺序与时刻 |
| git commit 时间与作者 | 代码是谁、什么时候写进去的 |
| `docs/evidence/` 截图/录屏 | 界面的实际状态，非纸上描述 |
| CI 运行记录 | 每次提交都真实构建过 |

## 五、纪律

- 部门之间不越权改对方的产物，发现问题写留痕 + 交给统筹
- 所有产物必须能追溯到一条留痕
- 留痕只追加，不修改历史
