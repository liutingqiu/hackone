## 一、二阶段要解决什么

一阶段解决「**图出得来**」，二阶段解决「**图用得起来**」。

用户拿到 5 页 PDF 之后的真实动作：打印 → 摊开 → 数格子 → 拼到一半不知道拼到哪 → 发现缺色 → 去淘宝一个个搜。
这四个环节，我们目前只覆盖了第一个。

**目标**：把「拿到图纸之后」补完，让产品从"生成器"变成"陪你搭完"。

## 三、方向 A：拼装引导

### 调研发现（决定了差异点在哪）

- LDB 与 Zippland **都已做「按色分批」**：整色高亮 + 当前色进度（R01 0/300）
- Zippland 点一次确认键把**整色**记为完成，自动跳下一色
- **两家都不保存进度**：刷新即回到 0/300；localStorage 里只有配色与尺寸，没有进度键
- 跨品类标准做法（Pattern Keeper，十字绣，9 美元买断）：符号高亮 + 逐格标记 + 完成率统计
- 「点一颗划一颗」在 LDB 里**实测未跑通**（长按也没让计数从 0 动），不能当卖点吹

**所以我们的差异不是"高亮"（已有），而是：进度持久化 + 与分板绑定。**

### 做什么（今天）

1. 按色分批高亮（选色号 → 该色高亮、其余灰显）—— 对齐竞品基线
2. **点一颗划一颗**（真正可用版：含放大镜与吸附，否则手机点不准）
3. **进度持久化**：patternHash + 完成格 bitmask 存 localStorage，换图不串、刷新不丢
4. **进度按板统计**：「第 2 块板已完成 37%」—— 四家竞品都没有

### 不做什么
- 账号与云端同步（V2）
- 多设备实时协作
- 语音引导

### 验收
- 选色 → 高亮 → 点 10 颗 → 进度 0→10 → 刷新后仍是 10
- 切换色号，已标格不被清空
- 换一张图，进度不串
- 10000 格（100×100）标记响应 < 50ms
- 手机 390px 宽下能准确点中目标格（放大镜吸附生效）

### 成本与风险
- 成本：3–4 小时（含放大镜）
- 风险：中。格子多时的重绘与命中判定是主要坑

## 四、方向 B：色卡校准（**不做**）

### 调研结论
- 没有任何拼豆工具做拍照校准
- 跨品类答案很硬：十字绣 100 年靠**实物线卡**（DMC 360 色），摄影靠灰卡与受控光源
- 物理原因：照片色 = 豆子真色 × 光照偏移，**无参照物时数学上不可分离**；手机还会自动白平衡/HDR 逐帧改参数
- 能做 demo，但**换台手机结果就变**，评委一试就穿

### 处置
本阶段不做，写进 V2 与白皮书风险节。将来若做，必须先解决参照物（随附标准色卡或让用户拍灰卡）。

## 五、方向 C：采购闭环（只做浅层）

### 调研结论
- **淘宝未登录搜索被风控挡住**（实测三个色号全部「请登录」），跳转是否命中正确商品**未验证**
- 需求真实：淘宝有「拼豆自选色」按色号选配商品，小红书有「补豆焦虑」内容
- 「一键配齐」的平台级产品未找到

### 做什么
1. **主路径：一键复制购物清单**（纯文本：色号 + 数量 + 总计），可直接粘给店家或搜索
2. 辅助：每行「去购买」跳淘宝搜索（搜索词而非商品链接，规避失效与风控）
3. 导出 PDF 的用量清单保留色号与数量

### 明确不做
- 不承诺「一键配齐」（会被追问价格库存，答不上来更糟）
- 不做价格抓取、库存、下单、支付

### 验收
- 复制出的文本可直接粘进微信/淘宝搜索框，格式可读
- 点「去购买」新开标签，搜索词含色号

### 成本
20–30 分钟。
