## 二、v1.5 — 进度、换品牌、核验和分享不再写坏数据

### 1.1 标记

拖动标记时，整段手势跟按下的那一格走。那一格还没拼，划过的格子都标上；那一格已经拼了，划过的格子都取消。不再逐格翻转。

### 1.2 换品牌可以撤销

切换品牌前先拍一张快照，里面带着当时的品牌和色号索引。撤销先回到旧品牌，再撤销换品牌之前的笔画。旧笔画不再被就地改写成新色板的索引。同一品牌里切换色号体系只改标签，不重映射格子。

### 1.3 拍照核验

和图纸色差小于 8 才算这一格对上。匹配格子不到图案的 40%，或者疑似错位比匹配还多，只在画面上标红框，**不写入拼装进度**。对得上的照片仍会把匹配格子标成已拼。

### 1.4 高分屏收起侧栏

「当前是不是适应窗口」改为比较画布的 CSS 尺寸和视口。2x 屏上收起侧栏后，本来适应窗口的图纸会重新适配；已经手动放大的缩放保持不动。

### 1.5 整理配色

整理改的是未限色的 `base`。被「最多色数」藏起来、又没有被这次合并点名的颜色还在。把色数上限调高，这些颜色还能回来。孤立杂色的清理结果会写回对应格子。

### 1.6 分享短链

链接长度不变，仍是 7 位 id。写入后会读回确认，确认到的不是自己的内容就换一个 id，避免两个并发请求盖掉同一条短链。读取缓存从一年改成 180 天，和 KV 的过期时间一致。同一 IP 每小时最多成功保存 30 次，超出返回 429，页面会改用离线长链接或导出文件。

### 1.7 其它

- 去背景的边缘容差从加权距离 60 调到 900，JPEG 白底的轻微噪声可以去掉，饱和色不会被当成背景。
- A4 单板页标题上的色数和颗数改成本板统计。
- 采购搜索词改用当前品牌 / 色号体系，不再写死 MARD。
- 画布改动在停手约 0.25 秒后写入 IndexedDB；关页时强制刷新缩略图。悬停在一格格大小的铅笔上不再整帧重画。缩小重采样时，近色匹配共用一块缓存。

## 四、v1.3.1 — 撤销不再清空拼装进度

**问题**：点一次「撤销」，右侧拼装进度归零，已标记的格子全丢。

**原因**：撤销/重做恢复图案时走的是 `installDoc()`；上一版为了"换图要清进度"，把清空逻辑写进了这个函数，于是任何一条撤销记录（画笔、整理、改尺寸、重新识别）都会顺手把进度表重建。

**修复**：

- `installDoc()` 不再触碰进度；只有"换图 / 新建空白 / 打开分享图纸"三个入口显式调用 `resetProgress()`；
- 撤销快照带上进度位图，撤销「新建空白」「整理」时，已拼记录跟着一起回退；
- 只有画布尺寸真的变了才重置（格子对不上，保留反而是错的）。

**验证**：标 10 颗 → 画一笔 → 连续撤销，进度稳定在 `10 / 1600`；线上标 3 格后连点 4 次撤销，仍为 `3 / 1600 · 0.2%`，第 4 次因历史为空才提示「没有可撤销的操作」。

## 五、v1.3 — 工具与模式合并，进度不再被"整理"清零

### 行为变更（破坏性）

**取消「浏览 / 标记」两态切换，标记降级为工具栏里的一个工具。**

原因不是交互偏好，而是状态机设计错误：模式与工具是两套并列状态，任何一边动作都会踢掉另一边——第一版切工具会把模式踢回「浏览」，第二版改成"标记模式下锁死工具栏"，都只是症状。本质是：「浏览」就是「查看」工具，它没有独立存在的理由。

现在只有一档状态：

```
查看 | 标记 ‖ 铅笔 橡皮 吸色 直线 矩形 圆形 连选填色 翻转
```

- 标记以绿色高亮，点格子切完成态，拖动连续标记，只记进度不动图案；
- 选任何工具都不再"跳模式"，因为没有模式可跳；
- 工具条右侧常驻一行说明，写清当前工具点下去会发生什么。

### 修复

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 点「整理 → 应用整理」后拼装进度归零 | 进度按整张图案的 hash 校验，hash 一变就整表重建；整理改色不改形，却被当成"换了张图" | 只在画布尺寸变化时重置 |
| 点「翻转」后画布点什么都没反应 | 翻转按钮没有 `data-t`，通用工具点击处理器把 `S.tool` 设成了 `undefined` | 动作按钮不再进入工具分支 |
| 翻转后已拼标记错位 | 进度位图没有跟着镜像 | 翻转时同步镜像进度 |
| 「打开图纸」看不出要什么文件 | 只有原生 title | 增加小圆角气泡：需要 .json 图纸文件 |
| 分享失败统一提示「网络不通」 | 未区分 HTTP 状态 | 区分「图纸太大（>400 KB）」与「网络不通」，并自动重试一次 |

### 精简

「按尺寸反推」独立模块删除。它是计算器，不在「导入 → 出图 → 拼装 → 采购」主链路上；用户真正需要的是"我这块 32×32 拼出来多大"。换算压成「新建画布」下方一行实时提示：

```
成品约 8.3 × 8.3 cm · 1024 颗 · 4 块底板（2.6mm 豆）
```

## 六、v1.2 — 画布能拖了，分享链接能发了

### 新增：画布拖拽平移

**问题**：放大后拖不动画布，Windows 队友却可以。

**结论**：不是操作系统问题——这个版本之前**根本没有平移实现**，只能靠浏览器原生滚动条；Windows 触控板两指拖动、中键自动滚动恰好能滚，Linux 上只有竖直滚轮，于是看起来像"Linux 不支持"。

现在三种手势，跨平台一致：

| 手势 | 行为 |
| --- | --- |
| 中键拖动 | 任意工具下平移（顺手屏蔽 Linux 中键粘贴） |
| 空格 + 左键拖动 | 任意工具下平移 |
| 查看工具下左键拖动 | 拖动即平移；不移动的单击仍然是查看格子 |

「查看」的选中动作从鼠标按下改到松开，避免拖动时误选。

### 新增：分享短链

原先分享把整张图纸压进 URL，微信、QQ 里根本发不出去。现在图纸存在服务端（Cloudflare Worker + KV），链接只有 38 个字符：

```
https://hack.liutingqiu.xyz/#s=j9pqp69
```

- 服务端限制单张 400 KB，有效期 180 天；
- 没网时自动退回 `#d=` 直连长链接；再放不下就导出 `.pinda.json`，用「打开图纸」打开；
- 实测：90×90 / 4 色图纸，链接 38 字符，新标签页打开完整还原；照片级 300×400 图纸包体约 197 KB。

### 改进

- 「整理」卡片把「应用整理 [执行]」合并成一个全宽按钮，少一次视线跳转；
- A4 每板页增加「本板用色 N 色」色单与 10 cm 比例尺（按 100% 打印，勿缩放）。

## 八、v1.0 — 产品定稿

从"能出图"到"能交付"：

- **单文件应用**：一个 HTML 带走全部功能，离线双击即用；
- **配色**：MARD 291 真实色板，另含 Hama / Perler / Artkal-S / 卡卡 / 石石 / 同趣 / 优肯 / DMC 共 9 个品牌 1751 色，支持品牌切换与近似色替换；
- **识别**：CIEDE2000 / Lab 欧氏 / RGB 加权三种算法，抖动、去背景、最多色数限制；
- **编辑**：铅笔、橡皮、吸色、直线、矩形、圆形、连选填色（4 连通）、左右翻转，笔刷 1–16，形状可实心；
- **画布**：多画布管理（IndexedDB 持久化、缩略图、改名、删除），上限 400×400；
- **导出**：A4 分板拼装图（总览 + 每板一页，1240×1754 px ≈ 210×297 mm）、PNG、CSV 采购清单；
- **配色整理**：合并强度（ΔE 阈值）与孤立杂色清理，可撤销。

### 早期修掉的问题（v1.0 之前）

| 现象 | 根因 |
| --- | --- |
| 「显示设置」点一次没反应（或需要点两次） | 模板被整段插入两次，页面上出现了两个同 id 按钮，事件绑了两遍 |
| 初始化中断：品牌下拉为空、缩放失效 | 移除了 `palInfo` 节点，但构建色板时仍在写它 |
| 点「新建空白画布」直接卡死 | 按钮处理器调用了自己，无限递归 |
| 长按步进器，画布出现拉伸条纹 | 每 +1 都触发一次重采样，累积误差；改为松手一次性提交 |
| 色号被截断（A07 显示成 07） | 格子过小 / 文本宽度不足；改为按格子尺寸动态选字号并保证完整色号 |
| 导入后画布不自动适配 | 补 fit，并保留手动缩放 |
| 每次刷新都弹「离开确认」 | `beforeunload` 绑定过宽；改为自动保存草稿，去掉拦截 |
| 手机端布局挤压 | 1000px 断点改单列布局 |

## 九、兼容性与迁移

- **数据**：画布存于浏览器 IndexedDB（库 `hackone`，表 `docs`），本版本升级**不清空**历史画布；进度随画布一起保存，切换画布自动恢复。
- **分享链接**：`#d=`（老长链接）与 `#s=`（新短链）两种格式同时可打开。
- **不再存在的东西**：`浏览/标记` 模式切换、「按尺寸反推」独立模块。老用户如果找不到它们，前者变成了工具栏的「标记」，后者变成了「新建画布」下方那行换算。

## 十、v1.6 九条已知问题的逐条处理

上一版列在这里的九条，这一版全部处理完，并逐条在真实浏览器里验证过。

| # | 问题 | 处理 | 验证 |
| --- | --- | --- | --- |
| 1 | 拍照核验没有透视校正 | 选完照片先进「四角框选」：默认贴照片边缘（等于老行为），拖过角才做透视变换 | 斜拍样张不校正 64/1600 匹配、405 错位；框好四角后 **1600/1600 全中** |

| 4 | 短链读取无鉴权 | **产品决策，不改**。拼豆图纸没有隐私诉求；id 不可猜、写入限流已就位 | — |
| 5 | 超大图纸首帧较重 | 引入脏行带重绘：一次改动只重画它所在的整行（上下各留 1 行），网格/色号/进度/预览仍复用同一段绘制代码 | 400×400 整帧 0.76ms → 0.32ms（**2.4×**） |
| 6 | 移动端未适配平移手势 | 单指拖动画布本来就通；这一版补上「第二根手指落下立刻转成捏合」，不再把它当平移 | 合成触摸下缩放 22 → 50.29，捏合后状态正确复位 |
| 7 | 平板竖屏只做抽屉降级 | 屏幕左右各加一条 **16×76 的边缘把手**，点它拉出抽屉，不再只能靠 banner 两个小按钮 | 820px 竖屏两把手可见，点击分别拉出左右抽屉，遮罩可关 |
| 8 | 相近色卡与色卡的层级不记忆 | 层级写进 `hc.palZ`，下次打开按上次的选择摆 | 点相近色卡 → 存 `sim` → 关掉重开仍是 sim 在上 |
| 9 | banner 触屏按钮 44×27 | 触屏热区改 44×36；工具条窄屏改成横向滑动，不再折成两行 | 390px 下 banner 与工具按钮均 44×36，工具条单行可横滑 |

顺带修掉的两个隐患：

- **脏行带坐标系**：`setTransform(dpr)` 之后一律按 CSS 像素算，避免行带整体贴偏 ×dpr；
- **`dr` 的声明位置**：它必须在 `requestDraw` 之前初始化，否则首屏会抛 TDZ 错误、核验只跑第一帧。

## 十一、已知问题（下一版处理）

| 问题 | 说明 | 影响 |
| --- | --- | --- |
| 短链依赖外网 | 无网时退回长链接/文件；链接 180 天后失效（设计边界） | 低 |
| 短链读取无鉴权 | 知道 id 就能读。写入每小时 30 次，已确认的 id 不会被并发请求覆盖（产品决策） | 低 |
| 四角框选未做自动检测 | 需要手动拖四个角；未来可尝试基于棋盘格的自动角点识别 | 低 |
