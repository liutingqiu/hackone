## 一、二阶段要解决什么

一阶段解决「**图出得来**」，二阶段解决「**图用得起来**」。

用户拿到 5 页 PDF 之后的真实动作是：打印 → 摊开 → 对着数格子 → 拼到一半不知道拼到哪 → 发现缺色 → 去淘宝一个个搜。
这四个环节，我们目前只覆盖了第一个。

**目标**：把「拿到图纸之后」补完，让产品从"生成器"变成"陪你搭完"。

## 三、方向 A：拼装引导

### 解决什么
老手回 Excel 的三条理由之一是「图纸是一张死图」——不能标记、不知道进度。新手则是「几十种颜色，不知道先拼哪个」。

### 做什么（48 小时内）
1. **按色分批高亮**：选一个色号，画布只高亮该色，其余变暗
2. **点一颗划一颗**：点击已拼格子标记完成，视觉上变灰/打勾
3. **进度显示**：本板 / 整图两个维度，"已拼 128 / 2304 颗"
4. **进度保存**：localStorage，刷新后回来接着拼

### 不做什么
- 不做账号与云端同步（V2）
- 不做多设备实时协作
- 不做语音引导

### 验收
- 选色 → 高亮 → 点 10 颗 → 进度 0→10 → 刷新后仍是 10
- 切换色号，已标记格子不被清空
- 10000 格（100×100）标记操作无可感卡顿（< 50ms 响应）

### 成本与风险
- 成本：2–3 小时（canvas 叠加层 + 状态 + localStorage）
- 风险：中。**格子多时的重绘性能**是主要坑

## 四、方向 B：色卡校准

### 解决什么
屏幕上的色值和手里的豆子有肉眼可见的差（ΔE 7.5 量级）。用户按屏幕选色，拿到手就偏。这是这个品类最底层、最没人解决的痛点。

### 做什么（条件式）
1. **完整版**：拍一张手中色卡 → 算用户这套豆相对标准色板的偏移 → 按偏移映射
2. **简化版**：不做自动校准，只做「手动微调」——对某个色号改一段色值偏移，全局生效

### 不做什么
- 不做多光源建模
- 不做专业色彩管理

### 验收（若做）
- 校准前后同一张图的色号映射变化可解释（不是乱跳）
- 结果可重置

### 成本与风险
- 成本：完整版 6–8 小时（48 小时内不可行）；简化版 2 小时
- 风险：**高**。白平衡/光照会让"校准"变成"猜"，**校准不准比不校准更糟**
- 决策条件：调研确认有无公开可行方案；若无，只做简化版或推迟 V2

## 五、方向 C：采购闭环

### 解决什么
用量清单是"知道买什么"，不是"能买到"。用户还要去淘宝一个个搜色号。

### 做什么
1. 用量清单每行加「去购买」链接，跳淘宝搜索「MARD A07 拼豆」
2. 导出 PDF 的用量清单保留色号与数量，便于一次性下单
3. 顶部加「一键复制采购清单」（纯文本，可直接粘给店家）

### 不做什么
- 不做价格抓取、库存查询（要爬虫，不稳定且涉合规）
- 不做支付/代购

### 验收
- 点任一行「去购买」，新标签打开淘宝搜索结果，关键词含色号
- 「复制清单」文本可直接粘到聊天窗口，格式可读

### 成本与风险
- 成本：20–30 分钟
- 风险：低。用搜索链接而非商品链接即可规避失效
